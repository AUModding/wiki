当你接触编程之前，你觉得编程里全是些夸张吓人的陌生单词 ~~（这些文字都是中文，为什么我看不懂？！）~~，好消息是，即便你有了C#的基础，情况仍然是这样！下面这些会经常用到，请尽量记住：

- **缓存（Cache）：** 缓存本质上是存储。如果你有一个经常
使用的值，就把它*缓存*起来（存进变量）。主要好处是
电脑不必反复计算或初始化新值。
数据已经在那里了，直接用就好。

- **垃圾回收器（GC，Garbage Collector）：** 如果硬要说开发模组的最大的敌人，GC 当之一提。GC 的主要工作是回收内存资源，
让你的模组不至于随时间不断吞噬 RAM。它明明很有用，为什么是敌人？
游戏中你感到的任何随机卡顿，通常都是因为你创建和销毁值太快，
让 GC 疲于奔命地替你善后。后面会详细讲。

- **反射（Reflection）：** 编程界的开锁术。它让
你的代码能在游戏运行时检查游戏的代码，更重要的是，
读写甚至调用原开发者特意藏起来的 `private` 或 `protected`
变量和方法。

- **Harmony：** 让现代模组开发不必永久破坏游戏原文件
成为可能的工具包。它让你在游戏运行时拦截其代码，
并安全地注入你自己的代码。

- **Prefix / Postfix：** 你使用 Harmony 的两种主要方式。Prefix 在
游戏原方法*之前*运行（适合修改输入，或完全取消原方法），Postfix 在
原方法*之后*运行（适合读取/修改最终结果，或添加额外的效果）。

- **互操作（Interop）：** IL2CPP 把游戏转换成了 C++，而你的模组
是用 C# 写的，两者语言不通。「互操作」就是坐在它们之间的翻译。
跨过这层翻译会消耗计算资源，所以要尽量避免频繁跨越，以免卡顿。

- **装箱（Boxing）：** 听起来像一项运动，但在 C# 里它是个性能陷阱。
当你把一个简单的轻量值（比如 `int` 或 `float`）
塞进更重的「对象」包装里时就会发生。这样做会产生多余的
垃圾，之后要由 GC 清理。如果你在快速运行的循环里不断装箱，
你的模组就会造成微卡顿。

- **LINQ（`System.Linq`）：** 一组神奇的 C# 命令（比如 `.Where()`、
`.Select()`、`.ToList()`），让列表查询变得极其简单易读。
但是 LINQ 出了名地在背后偷偷制造大量垃圾。它非常适合
游戏加载时只运行一次的代码，但把它用在 `Update()` 循环里
是游戏模组开发的大忌。

- **热路径 / 冷路径（Hot / Cold Paths）：** 当你预计一段代码每秒会
运行多次，它就是热路径。热路径上的内存分配要绝对保持最低。
冷路径是不怎么频繁运行的代码，在这里随便折腾 GC，
没人看着你，也没人评判你。

- **`空引用`（NullReferenceException）：** 你能见到的最常见的报错。
它意味着你的代码试图访问一个完全为空（`null`）的变量或对象。
相当于你伸手进口袋摸车钥匙，却抓了一把空气。

- **程序集（Assembly，或者说 .dll）：** 可以把它看作你模组的最终发布包。
编译 C# 代码后，它会被打包成动态链接库（DLL）。
这就是用户放进 `plugins` 文件夹见证奇迹发生的那个文件。
