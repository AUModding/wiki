作为一名初出茅庐的模组开发者，你可能会想：「代码能跑就行，为什么还要在意写得*好不好*？」

把它想象成一道你高中时破天荒做出来的大题。你会把步骤写得含糊不清吗？
会省略一些步骤吗？如果你写的某个步骤太糟糕，判卷老师是肯定不会给全分的。

在这个场景里，试卷就是用户的电脑。
计算机会老老实实地花时间做你让它做的多余事情。
如果你的答案写的太冗余，你不仅没地方写全答案，更会把用户的游戏拖到只剩 4 帧，更糟的是崩溃从而断开游戏。
CPU 飙满、黄金般的内存坏掉、散热萝卜都被煮熟了。想想就可怕！

当然也有例外，比如你自己、你的测试人员。
你们都*希望*报错出现，这样才能知道哪里出了问题并修复它。

你想让用户开心，最简单的办法就是写出好代码。

在本部分中，我们会带你了解编写整洁、优化良好的模组的核心原则。
不仅用户的电脑会开心，未来的你一定会感谢现在努力付出的自己。（什么鸡汤？）
没有什么比诊断一个像双缝干涉实验一样难以观察的 bug 更折磨人的了。
