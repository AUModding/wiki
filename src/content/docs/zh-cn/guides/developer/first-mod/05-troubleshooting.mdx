在写你的第一个模组，或者刚开始接触模组开发时，你可能会遇到各种自己不理解的问题。  
这里我们会尽可能覆盖这些常见问题，希望你能够快速解决它们并继续开发模组！

## 异常

### `NullReferenceException`（NRE）

你能见到的最常见报错。它表示你的代码试图访问一个完全为空（`null`）的变量或对象。
相当于你伸手进口袋摸车钥匙，却抓了一把空气。看到这个异常时，
建议从出错的方法里逐行排查，想想什么东西可能是 `null`。

## Harmony

### 内联方法

如果你的补丁附加到某个特定方法后却没有运行，这通常可能就是原因。  
Unity 的 IL2CPP 后端会把游戏的 C# 代码转换为 C++，之后经过 AOT 编译为原生代码。  
在这次编译过程中，编译器可能会**内联**方法，也就是说，对该方法的任何调用都会被展开为方法体。  
因此，Harmony 无法修改该方法，因为根本不存在可供修改的方法调用！

对于内联，你可以这样做：

- 改为给你的目标方法的调用方打补丁。给被内联方法的调用方打补丁通常有效，因为调用方通常更大，本身不太可能被内联。
- 给一个完全不同的方法打补丁。如果某个方法（甚至一系列方法）被内联了，通常有助于在打补丁时到别处寻找，因为其他方法可能没有被内联。
- 使用 [Mono Method Analyser](https://allofus.dev/il2cpp/) 检查内联方法。
  这个工具可以让你浏览游戏的方法，并查看它们是否适合安全地打补丁。  
  关于如何使用该分析器的指南，请参阅<a href={getRelativeLocaleUrl('zh-CN', "resources/method-analyser")}>使用方法分析器</a>。
