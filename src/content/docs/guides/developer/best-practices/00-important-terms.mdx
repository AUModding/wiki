---
title: Important Terms
description: Specifies important terms and information to remember.
---

All of programming involves big, scary words. The following will be used
often, so do your best to remember them:

- **Cache:** A cache is essentially storage. If you have a value you tend to
use often, you *cache* it (save it to a variable). The main benefit is that
your computer won't have to repeatedly calculate or initialize new values.
The data is already there, so you might as well reuse it.

- **Garbage Collector (GC):** If you need an enemy to fight, the GC is a
prime candidate. The GC's main job is to reclaim memory resources so your mod
doesn't just keep eating RAM over time. It's useful, so why is it our enemy?
Well, any random lag spike you feel in-game is usually caused by you creating
and destroying values too quickly and letting the GC run rampant cleaning up
after you. More on that later.

- **Reflection:** The programming equivalent of picking a lock. It allows
your code to inspect the game's code while it is running, and more
importantly, read, run or change `private` or `protected` variables and
methods that the original developers explicitly tried to hide from you.

- **Harmony:** The toolkit that makes modern modding possible without
permanently corrupting the game's original files. It lets you intercept the
game's code while it's running and safely inject your own.

- **Prefix / Postfix:** The two main ways you will use Harmony. A Prefix runs
*before* the game's original method (great for modifying inputs, or
cancelling the original method entirely), and a Postfix runs *after* it
(great for reading/editing the final results or adding extra effects).

- **Interop:** Since IL2CPP converts the game into C++, but your mod is
written in C#, they speak different languages. "Interop" is the translator
sitting between them. Crossing this translation boundary takes computational
effort, so you want to cross it as little as possible to avoid lag.

- **Boxing:** Sounds like a sport, but in C#, it’s a performance trap. It
happens when you take a simple, lightweight value (like an `int` or a `float`)
and stuff it inside a heavier "object" wrapper. Doing this creates unnecessary
garbage that the GC has to clean up later. If you box values constantly in a
fast-running loop, your mod will cause micro-stutters.

- **LINQ (`System.Linq`):** A magical set of C# commands (like `.Where()`,
`.Select()`, or `.ToList()`) that makes searching through lists incredibly easy
and readable. However, LINQ is notorious for secretly creating a massive amount
of garbage behind the scenes. It's fantastic for code that runs once when the
game loads, but using it inside an `Update()` loop is a cardinal sin of game
modding.

- **Hot / Cold Paths:** When you expect to run a piece of code multiple times a
second, that is a hot path. You absolutely want to keep allocations here to a
minimum. A cold path is a piece of code that doesn't run as frequently. Feel
free to thrash the GC here, no one's looking or judging.

- **`NullReferenceException` (NRE):** The most common error you will ever see
in your console. It means your code tried to interact with a variable or
object that is entirely empty (`null`). It is the programming equivalent of
reaching into your pocket for your car keys and grasping empty air.

- **Assembly (.dll):** Think of this as the final shipped package of your
mod. When you compile your C# code, it gets bundled into a Dynamic Link
Library (DLL). This is the physical file users will drop into their `plugins`
folder to make the magic happen.
