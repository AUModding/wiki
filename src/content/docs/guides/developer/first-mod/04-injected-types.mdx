Unity is a component-based game engine, [MonoBehaviours](https://docs.unity3d.com/6000.6/Documentation/Manual/class-MonoBehaviour.html) are attached to [GameObjects](https://docs.unity3d.com/6000.6/Documentation/ScriptReference/GameObject.html) to drive specific functionality.
This is needed for more complex functionalities.

## Creating a new MonoBehaviour

You can create a new MonoBehaviour like so:

```csharp
using System;
using UnityEngine;

namespace YourMod.Modules.Components
{
    public class CustomMonoBehaviour(IntPtr ptr) : MonoBehaviour(ptr)
    {
        private void Start() {} //Gets called when the component is first enabled.
        private void Update() {} //Gets called every frame.
    }
}
```

## Registering the MonoBehaviour

If you're using [Reactor](https://github.com/NuclearPowered/Reactor), you can use the `[RegisterInIl2Cpp]` attribute on your class to register it.
This has a small drawback of not having control over which types get registered first.

A better approach is using the `ClassInjector` class and calling `ClassInjector.RegisterTypeInIl2Cpp<CustomMonoBehaviour>();` in your plugin's `Load` function.

## Registration Order

Order is important if you have multiple custom MonoBehaviours that depend on **one another**, so a specific order is needed.

## Accessing fields set within Unity's Inspector

If you have a prefab in Unity with a custom MonoBehaviour, and try loading it into the game through an AssetBundle, you may notice that the values you set in editor are **lost**, to preserve them, you should use ```Il2CppReferenceField<T>``` In your MonoBehaviour (in the mod's codebase), ```T``` being the type of the object, for values like integers, floats ect, use ```Il2CppValueField<T>```.

:::note
the Class, namespace, and field names **must match** in both your Unity project and mod.
:::
