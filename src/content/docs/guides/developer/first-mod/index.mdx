Welcome to this step-by-step guide on making your first Among Us mod.
It is recommended that you first follow the [environment setup guide](/guides/developer/environment/) before continuing.

Before we start, you need to have the following:

- A decent computer. At least 8GB RAM is recommended.
- The [.NET SDK](https://dotnet.microsoft.com/en-us/download). Any modern version should work.
- An IDE suitable for .NET. Examples include [VS Code](https://code.visualstudio.com/download),
[JetBrains Rider](https://www.jetbrains.com/rider/),
and [Visual Studio](https://visualstudio.microsoft.com/).
- Some kind of programming background.

This guide assumes you already have experience with object-oriented languages like C# or Java.
If you are new to C#, you can learn at [freeCodeCamp](https://www.freecodecamp.org/) or [Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/csharp/).

## Installing the .NET SDK

Hopefully you don't struggle with this part, otherwise you're gonna have a bad time.

Installing .NET should be easy, just go to the official .NET [download page](https://dotnet.microsoft.com/en-us/download)
and grab the latest version of the SDK for your platform. Even though Among Us mods are developed for .NET 6.0,
modern SDK versions can still compile programs made for older versions. Just use the latest available SDK.

If you are trying to develop mods on a mobile device... please don't.
Installing the .NET SDK and an IDE is much more difficult on mobile.
If you can figure it out, go for it, but we won't discuss that here.

## Installing an IDE

To actually write code, you will need an IDE (Integrated Development Environment). Most mod developers recommend Rider or VS Code.
Beginners usually start with VS Code, but Rider comes with some features you won't find in VSC.
Review the following options and make a choice:

- **JetBrains Rider**: A full .NET IDE with C# and Unity support, autocomplete, syntax highlighting,
debugging, and more. It can be a bit resource-intensive, but a good option overall. You can download
it [here](https://www.jetbrains.com/rider/).

- **Visual Studio Code**: Lightweight and open-source. You can install extensions for C# and Unity to get
nearly the same feature-set as JetBrains Rider. A good choice for saving memory and disk space.
Download it [here](https://code.visualstudio.com/download).

- **Visual Studio**: A full .NET IDE with the various features mentioned above. It basically does what
Rider does, but can be heavier on your CPU and memory. More complex than VS Code as well.
You can download it [here](https://visualstudio.microsoft.com/).

- **No IDE (Text Editor)**: It's included with your platform, like Notepad on Windows, but you don't get
anything to help you write code. No syntax highlighting, no autocomplete, nothing. This option is **not recommended**.

## Viewing Decompiled Code

Thankfully, InnerSloth is merciful enough to provide modders with the `Assembly-CSharp.dll` file from the Mono build of Among Us,
before they run the IL2CPP process. Since the Mono DLL is IL code, it makes it easy for modders
to find out how the game works internally without using a disassembler like IDA or Ghidra.
You can view the decompiled code with our [Code Inspector](https://code.aumodding.dev) or using one of the tools mentioned below.

- **[dnSpy (dnSpyEx)](https://github.com/dnSpyEx/dnSpy)**: Simple and convenient decompiler which provides assembly analysis tools 
with fast navigation for exploring the game's code. This is a maintained fork of the original archived project.
- **[ILSpy](https://github.com/icsharpcode/ILSpy)**: Lightweight decompiler that is actively maintained and allows for quick code
reading with a simple interface. It is available on Windows, Mac and Linux, while the other two options are Windows-only.
- **[dotPeek](https://www.jetbrains.com/decompiler/)**: A heavier decompiler created by JetBrains, with UI and navigation
that is similar to their IDEs. However, unlike the other two options, it is not open-source.
