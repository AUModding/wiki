### .NET Runtime

The [.NET Runtime](https://en.wikipedia.org/wiki/.NET) is the environment in which applications written in C#
(among other supported languages) are executed. It is essentially the underlying program that runs your C# code
by compiling it into [IL](#il-intermediate-language) and handling things like memory management at runtime. If you are familiar
with Java development or Minecraft modding, the .NET Runtime is the equivalent of the JVM. In Among Us modding,
mods run on a .NET runtime hosted inside the game.

### IL (Intermediate Language)

Similar to assembly language, but for the .NET runtime
instead of your computer. C# programs are compiled into IL, then .NET compiles that IL into assembly
for your specific machine at runtime. This is called Just-In-Time, or JIT, compilation.

### Just-In-Time (JIT)

JIT compilation allows the .NET Runtime to convert IL code into native machine instructions while the program is running.
In the context of Among Us mods, the runtime reads the IL in your mod DLL and compiles it to native code when it's needed.
This makes it easier to run cross-platform apps, but comes at the cost of slower app startup and increased memory usage.

### Ahead-Of-Time (AOT)

AOT compilation turns source code directly into assembly code without any runtime compilation.
The main benefits of AOT are faster startup times, lower memory usage, and lower CPU usage.
AOT is also required for some platforms, like iOS, which do not allow JIT programs to run.
In the context of Among Us modding, the game itself uses AOT because it is built with IL2CPP.

### Assembly (.dll)

Think of this as the final shipped package of your mod. When you compile your C# code, it gets bundled into a
Dynamic Link Library (DLL). This is the file users will drop into their `BepInEx/plugins` folder to run your mod.
DLL files can also be used for adding dependencies or other external code to your project.
